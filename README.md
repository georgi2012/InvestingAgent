# AI Investment Agent

A local multi-agent stock analysis app that combines a Flask backend, TradingAgents orchestration, and a dark-themed dashboard UI.

The app runs a full analyst-to-portfolio-manager pipeline, streams agent progress in real time, caches latest per-ticker analysis, and stores run history in SQLite.

## What This Project Does

- Accepts a stock ticker and analysis date.
- Runs a staged multi-agent workflow with configurable provider and model pair.
- Streams live logs and pipeline step status while analysis is running.
- Produces a final BUY / SELL / HOLD recommendation with full reasoning output.
- Caches latest analysis per ticker for fast reruns.
- Persists recent analysis history for browsing and rerunning.

## Agent Pipeline Architecture

This system implements a role-specialized, graph-orchestrated multi-agent inference pipeline for equity analysis.  
Agents are intentionally separated by function (signal extraction, adversarial reasoning, execution planning, and risk governance), then merged into a final portfolio decision.

### Execution Graph

1. `fundamentals` (quick model): valuation, growth, profitability, balance-sheet signals.
2. `sentiment` (quick model): retail/market mood extraction from social and news context.
3. `news` (quick model): event-level and macro narrative extraction.
4. `technical` (quick model): momentum/volatility pattern context.
5. `bull` researcher (deep model): constructs strongest pro-position thesis.
6. `bear` researcher (deep model): constructs strongest contra-position thesis.
7. `debate` (deep model, N rounds): adversarial refinement between bull and bear theses.
8. `trader` (deep model): synthesizes a concrete trade recommendation.
9. `risk` manager (deep model): applies downside/risk controls to proposal.
10. `portfolio` manager (deep model): emits final BUY / SELL / HOLD decision.

### AI System Design Notes

- **Graph orchestration**: execution is driven through `TradingAgentsGraph`, preserving deterministic stage order while allowing model/provider interchange.
- **Model routing policy**: fast/low-cost models handle broad signal fan-out (`fundamentals` -> `technical`); high-capability models handle synthesis, adversarial debate, and governance.
- **Adversarial reasoning loop**: explicit bull-vs-bear rounds reduce one-sided bias and improve argument robustness before trade proposal generation.
- **Context control**: LangChain chat batches are bounded to `100k` chars to reduce overflow and hard failure risk on long chains.
- **Failure strategy**: transient transport/API errors trigger up to 3 attempts with graph rebuild, improving resilience during unstable provider windows.
- **Provider abstraction**: OpenAI, Azure OpenAI, Anthropic, and Ollama are supported through a unified config path.
- **Azure compatibility layer**: requests are normalized to `/openai/v1/*`, and deployment-name semantics are enforced.

### External Signal Enrichment (Sentiment/News)

The sentiment/news stage augments internal reasoning with live external sources:

- Reddit search feeds (`wallstreetbets`, `stocks`, `investing`, `options`)
- RapidAPI `stocktwits-sentiment-message-analytics-api`
- RapidAPI `yahoo-finance15`
- RapidAPI `yh-finance`
- Free Yahoo Finance search endpoint
- Free Yahoo Finance RSS endpoint

News payloads are merged and deduplicated before injection into the agent context.

## Tech Stack

- Backend: Python, Flask, Flask-CORS
- Agent graph: `tradingagents`, `langgraph`, `langchain`
- Model clients: OpenAI / Azure OpenAI / Anthropic / Ollama
- Storage: SQLite (`results.db`)
- Frontend: HTML/CSS/JS (`templates/main-index.html`)

## Project Structure

- `main-app.py` - primary app entrypoint and API backend
- `templates/main-index.html` - redesigned dark-mode dashboard UI
- `results.db` - SQLite database for history and cache
- `results/` - per-ticker output artifacts/logs generated by agent runs
- `app.py` and `templates/index.html` - older/original app version retained

## Database Model

Two tables are auto-created:

- `results`
  - stores historical analysis runs
  - includes ticker/date/provider/models/decision/output/created timestamp
- `analyst_cache`
  - one row per ticker
  - stores latest cached analysis payload and cache timestamp

## API Endpoints

- `GET /` -> serves `main-index.html`
- `POST /api/analyze` -> starts async analysis job
- `GET /api/status/<job_id>` -> returns live job state and streamed logs
- `GET /api/cache/<ticker>` -> cache metadata lookup
- `DELETE /api/cache/<ticker>` -> clears cached ticker entry
- `GET /api/results` -> latest analysis history list
- `GET /api/results/<id>` -> full history entry
- `DELETE /api/results/<id>` -> delete history entry
- `GET /api/ollama/models` -> local Ollama availability and model tags
- `GET /api/suggested_date` -> returns a recent business-day date

## Setup

## 1) Create and activate environment (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

## 2) Install dependencies

Use your project requirements if available. If not, install the key runtime packages:

```powershell
pip install flask flask-cors requests certifi openai anthropic langchain langchain-openai langgraph tradingagents
```

## 3) Configure environment variables

Set these in the shell before running:

```powershell
$env:AZURE_OPENAI_ENDPOINT="https://<your-resource>.openai.azure.com/"
$env:AZURE_OPENAI_API_KEY="<your-key>"
$env:AZURE_OPENAI_DEEP_DEPLOYMENT="gpt-5.4"
$env:AZURE_OPENAI_QUICK_DEPLOYMENT="gpt-5.4-mini"
$env:RAPIDAPI_KEY="<optional-rapidapi-key>"
```

Optional proxy cleanup when local proxy interferes:

```powershell
Remove-Item Env:HTTP_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:HTTPS_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:ALL_PROXY -ErrorAction SilentlyContinue
$env:NO_PROXY="localhost,127.0.0.1"
```

Optional permanent user-level env setup:

```powershell
[Environment]::SetEnvironmentVariable("AZURE_OPENAI_ENDPOINT", "https://<your-resource>.openai.azure.com/", "User")
[Environment]::SetEnvironmentVariable("AZURE_OPENAI_API_KEY", "<your-key>", "User")
[Environment]::SetEnvironmentVariable("AZURE_OPENAI_DEEP_DEPLOYMENT", "gpt-5.4", "User")
[Environment]::SetEnvironmentVariable("AZURE_OPENAI_QUICK_DEPLOYMENT", "gpt-5.4-mini", "User")
```

## Run

```powershell
python main-app.py
```

Open:

- `http://127.0.0.1:5000`

The app runs with `debug=False` and `use_reloader=False` to avoid duplicate Flask processes.

## Using the UI

- Enter ticker and date.
- Select provider and models.
- Pick debate rounds.
- Choose cache policy.
- Click `Run Analysis`.
- Watch the live pipeline and logs.
- Inspect final decision and formatted report.
- View, rerun, or delete history entries.

## Security Notes
- Keep secrets in user/system environment variables or secure secret stores.
- Review generated outputs before making any trading decision.
